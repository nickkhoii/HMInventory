# CODEX MASTER PROMPT
## HM Laboratory Inventory Management System

Act as a senior full-stack software engineer, database architect, UI/UX designer, QA engineer, and security engineer.

Your task is to design and develop a complete, functional, production-quality **Inventory Management System for the HM (Hospitality Management) Laboratory**.

This is a **single-user system**. There is only one authorized role:

**Administrator**

Do NOT create student, faculty, staff, custodian, or other user roles.

The Administrator has complete access to all system functions.

---

# 1. SYSTEM NAME

**HM Laboratory Inventory Management System**

The system will be used to manage, monitor, and document the equipment, tools, utensils, appliances, furniture, supplies, and other inventory items found inside the Hospitality Management laboratory.

The system must replace manual inventory records with a centralized digital inventory management platform.

# 10. STOCK-IN MODULE

Fields:

- Transaction Number
- Date
- Item
- Quantity
- Unit Cost
- Supplier
- Reference Number
- Remarks

When a Stock-In transaction is saved:

**Current Quantity = Current Quantity + Stock-In Quantity**

Maintain a permanent transaction history.

---

# 11. STOCK-OUT MODULE

Allow inventory quantities to be reduced.

Fields:

- Transaction Number
- Date
- Item
- Quantity
- Purpose
- Remarks

When Stock-Out is recorded:

**Current Quantity = Current Quantity - Stock-Out Quantity**

The system MUST prevent the Administrator from removing more quantity than is currently available.

Example:

Available = 10

Stock Out = 15

The transaction must be rejected with an appropriate validation message.

# 27. DATA INTEGRITY

Inventory quantities are critical.

Implement database-safe operations.

For every stock transaction:

1. Validate item.
2. Validate quantity.
3. Read current quantity.
4. Validate business rules.
5. Create transaction.
6. Update inventory quantity.
7. Create audit/activity record.
8. Commit everything atomically.

If any step fails, rollback the complete operation.

Never allow:

- Negative inventory
- Invalid quantities
- Duplicate inventory codes
- Orphan transactions
- Invalid foreign keys
